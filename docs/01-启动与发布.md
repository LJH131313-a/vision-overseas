# 启动、发布、更新与故障处理

## 一、本机启动（无需安装任何东西）

1. 打开本目录，**双击 `index.html`**。页面通过 `<script>` 标签加载数据（`data/vo-data.js`、`data/news.js`），不依赖 Python、Node 服务或数据库。
2. 项目数据保存在浏览器本机存储（localStorage）。若以 `file://` 方式打开，部分浏览器可能限制本机存储——推荐用 Chrome/Edge，或按下节通过本地静态服务/线上地址访问。
3. 「删除项目」「保存回复」等操作只影响本机浏览器数据，不影响网站文件。

> 说明：核心页面设计为无服务运行；但新闻**采集**程序需要 Python 或 GitHub Actions（见第四节）。

## 二、发布到 GitHub Pages（本仓库）

仓库：`https://github.com/LJH131313-a/vision-overseas`

### 首次或重建发布（分支方式，可保留旧版本）

1. 确认你对该仓库有推送权限（Settings → Collaborators，或仓库属于你）。
2. 本地准备：把本目录初始化为 Git 仓库并提交到独立分支（示例分支 `rebuild-v2`，不动 `main`，旧版本随时可回退）：
   ```bash
   cd 千问办公最终作品
   git init -b rebuild-v2
   git add -A
   git commit -m "远见·企业出海助手 重建版（整合三份原始交付物）"
   git remote add origin https://github.com/LJH131313-a/vision-overseas.git
   git push -u origin rebuild-v2
   ```
   推送时浏览器会弹出 GitHub 登录（或使用 Personal Access Token 作为密码）。
3. 打开仓库 **Settings → Pages**，在 Build and deployment 中选择 **Deploy from a branch**，分支选 `rebuild-v2`、目录 `/ (root)`，保存。
4. 等待 1–3 分钟，在 Settings → Pages 顶部打开生成的网址（形如 `https://ljh131313-a.github.io/vision-overseas/`）。
5. 验收要点：首页能打开；「数据说明」显示 86 条规则；新闻雷达显示快照条数与来源状态。

### 方式 B：使用已准备好的分支包（无需重新整理文件）

本目录已附带 `远见重建分支-rebuild-v2.bundle`（Git bundle，含完整 rebuild-v2 分支与提交）。在任意装有 Git 的电脑上：

```bash
git clone 远见重建分支-rebuild-v2.bundle rebuild-v2
cd rebuild-v2
git push https://github.com/LJH131313-a/vision-overseas.git rebuild-v2
```

推送时按提示登录 GitHub（浏览器授权或 Personal Access Token）。随后按上面第 3–5 步开启 Pages。

### 回退旧版本

- 旧版本仍在原分支（如 `main`）。回退 = 在 Settings → Pages 把发布分支改回 `main`，保存即可，旧内容不会丢失。
- 也可用 `git log` 找到旧提交，`git checkout <commit>` 后另行建分支发布。

## 三、日常更新网站内容

1. 修改页面/数据文件后在本地打开确认。
2. 提交并推送到**发布分支**：
   ```bash
   git add -A && git commit -m "说明：改了什么" && git push
   ```
3. GitHub Pages 会自动重新发布，1–3 分钟后刷新页面（必要时 Ctrl+F5 清缓存）。

## 四、新闻定时更新（GitHub Actions）

- 工作流：`.github/workflows/update-news.yml`。**定时任务（非实时监控）**：北京时间约 **09:17 与 17:17** 各执行一次；也可在仓库 **Actions → 更新新闻快照 → Run workflow** 手动运行。
- 流程：`tools/collect_news.py` 抓取 `news/feeds.json` 中 11 个政府官方 RSS/Atom 来源 → 与既有快照合并去重（按标题+链接指纹；最多保留 1200 条、240 天窗口）→ 输出 `data/news.json` 与 `data/news.js` → 自动提交回发布分支 → GitHub Pages 重新发布。
- 首次使用前确认：仓库 **Settings → Actions → General → Workflow permissions** 选择 **Read and write permissions**（工作流需要写回快照）。
- 部分来源失败：保留成功来源与历史新闻，来源状态表中标红显示失败原因；全部失败：完整保留最后一次成功快照并在页面新闻模块显示「采集全部失败」状态。
- 采集遵守来源站点的访问限制（标准 User-Agent、不重试轰炸、不绕过 403/429）。

### 本机手动更新（可选，需要 Python 3.10+）

```bash
python tools/collect_news.py          # 联网采集并合并
python tools/collect_news.py --offline  # 不联网，仅重建 news.js
```

没有 Python 时，可用 Node 只重建包装文件（不采集）：`node tools/rebuild_news_js.mjs`。

## 五、常见故障处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面空白 / 数据缺失 | `data/vo-data.js`、`data/news.js` 未随仓库提交 | 检查文件是否在发布分支；重新提交 |
| 新闻模块显示「快照为空或未加载」 | `data/news.js` 缺失 | Actions 跑一次采集，或本地 `node tools/rebuild_news_js.mjs` |
| Actions 定时任务没跑 | 默认分支上的工作流才会定时执行；或 Workflow permissions 未开 | 把工作流合入**默认分支**；检查 Settings → Actions 权限 |
| Actions 推送被拒 | Workflow permissions 只读 | Settings → Actions → General → Workflow permissions → Read and write |
| 某些新闻来源一直失败 | 来源网站改版或限制访问 | 页面会如实显示失败状态；人工核对来源 URL 后更新 `news/feeds.json`，不要绕过访问限制 |
| GitHub Pages 404 | 发布分支/目录选错 | Settings → Pages 检查分支与 `/ (root)` |
| 更新后看到的还是旧页面 | CDN 缓存 | 强制刷新（Ctrl+F5）或等几分钟 |
| 本机存储不可用（隐私模式） | 浏览器限制 localStorage | 用常规窗口打开；页面会提示「仅当前会话有效」 |
| 页面上出现「需要重新分析」 | 输入指纹与保存的千问回复/快照不一致 | 这是预期行为：重新生成任务、重新分析后再次保存 |
